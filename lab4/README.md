## 2. Тема роботи

Доопрацювання створеного раніше Unity-прототипу гри `System Breach: Overdrive` через упорядкування повторно використовуваних ігрових об'єктів, додавання Object Pool та відображення стану пулу в інтерфейсі.

## 3. Мета роботи

Покращити базовий ігровий прототип без зміни основної концепції гри: використати наявні графічні асети, зберегти існуючий HUD, створити повторно використовуваний об'єкт вузла сітки та замінити постійне створення/видалення вузлів на повторне використання через Object Pool.

## 4. Опис доопрацьованого прототипу

У прототипі вже була реалізована логічна 2D-гра, де гравець обертає вузли цифрової мережі та намагається побудувати правильний шлях сигналу від джерела до виходу до завершення таймера.

У межах лабораторної роботи 4 прототип доопрацьовано точково:

- залишено основний ігровий цикл без змін;
- використано наявні графічні асети вузлів і фону;
- додано prefab-шаблон `GridNode`;
- реалізовано Object Pool для вузлів ігрової сітки;
- додано HUD-індикатор стану пулу;
- замінено видалення вузлів при перезапуску рівня на повернення вузлів до пулу.

## 5. Перелік реалізованих елементів

### 5.1. Базові асети

У проєкті використано наявні графічні асети з папки:

- `Assets/Pipelines/bg.png` — фон сцени;
- `Assets/Pipelines/straight.png` — прямий сегмент мережі;
- `Assets/Pipelines/corner.png` — кутовий сегмент;
- `Assets/Pipelines/tee.png` — T-подібний сегмент;
- `Assets/Pipelines/cross.png` — перехресний сегмент.

Ці асети використовуються для візуального представлення вузлів цифрової мережі.

### 5.2. Prefab-об'єкт

Створено prefab-шаблон:

- `Assets/Prefabs/GridNode.prefab`

Він представляє базовий вузол ігрової сітки. У runtime-логіці вузли створюються та повторно використовуються через пул, але prefab лишається як зрозумілий шаблон основного повторюваного елемента гри.

### 5.3. UI-елементи

У HUD вже були реалізовані:

- номер рівня;
- таймер `SYSTEM HEALTH`;
- статус гри;
- прогрес цільових вузлів;
- меню, пауза, рестарт і екран результатів.

Для лабораторної роботи 4 додано окремий індикатор:

- `POOL A:x C:y R:z`

Позначення:

- `A` — кількість активних вузлів на полі;
- `C` — кількість вузлів, які зараз лежать у пулі;
- `R` — кількість повторних використань вузлів із пулу.

## 6. Опис роботи Object Pool

Object Pool реалізовано для об'єктів типу `GridNode`, тобто для вузлів ігрової сітки.

Раніше при генерації нового рівня старі вузли видалялися через `Destroy`, а нові створювалися через `new GameObject`. Після доопрацювання вузли не знищуються. При перезапуску або переході на інший рівень вони повертаються до пулу, деактивуються, а потім повторно використовуються для нового поля.

Порядок роботи:

1. На початку рівня пул видає потрібну кількість вузлів для сітки.
2. Якщо в пулі є вільні вузли, вони повторно активуються.
3. Якщо вільних вузлів не вистачає, створюються нові.
4. При генерації нового рівня активні вузли скидають стан і повертаються до пулу.
5. Після цього ті самі об'єкти можуть бути використані ще раз.

Це зменшує кількість постійних створень і видалень об'єктів під час роботи прототипу та демонструє базовий підхід до оптимізації повторюваних ігрових елементів.

## 10. Висновок

У межах лабораторної роботи 4 було доопрацьовано існуючий прототип гри `System Breach: Overdrive`. Основна логіка гри залишилася незмінною: гравець обертає вузли мережі та будує шлях сигналу.

Прототип став краще відповідати вимогам лабораторної роботи без зайвого розширення функціоналу.

Подальшого вдосконалення можуть потребувати додаткові візуальні ефекти та нові типи рівнів, але для демонстраційної версії лабораторної роботи реалізованих змін достатньо.
